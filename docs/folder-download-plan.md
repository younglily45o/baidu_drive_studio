# 文件夹下载与名称左对齐

用户要求文件名列左对齐，并能勾选、下载文件夹。保留“点击文件夹名称进入目录”，复选框用于选择文件或目录；“全选本页”包含目录。直链验证仍只对一个普通文件开放。

执行方式：直接扩展当前队列。点击下载后，含目录的批次在后台扫描所有子目录和分页，先形成完整下载计划；成功后创建目录（包括空目录），将普通文件按原目录层级加入现有队列。相比单独实现文件夹传输状态机，这样能复用逐文件取消、重试、进度、断点和禁止覆盖。扫描期间可取消，失败或取消不加入部分下载列表。

新增 `src/download_plan.rs`：保存根目录名和相对路径，验证远端父子路径、Windows 文件名、重复目标及目录循环；一批最多 50,000 个条目、深度最多 128 层。先扫描，后创建本地目录。已有正常目录可合并，已有文件阻止建目录；拒绝子目录符号链接及越界路径。下载同名文件沿用现有不覆盖行为。

`ui.rs`：增加独立目录扫描接收器和取消标记，扫描属于 busy 状态，退出/注销及取消全部同步处理；成功后向现有队列添加文件任务。文件名列标题和内容均左对齐，保留截断及完整路径提示。

批次入队使用目标集合，一次检查活动任务后线性追加；已在队列中的目标跳过并单独计数。传输卡片每页 100 项，取消全部仍覆盖完整队列。目录准备或取消后可能保留已经创建的空目录，不删除已有本地内容。

Windows 最终发布先规范化已有临时文件和目标父目录，得到扩展长度路径，再用不带覆盖标志的 MoveFileExW 发布。递归产生的长路径不依赖应用 manifest 的 MAX_PATH opt-in；依据 [微软 MoveFileExW 文档](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw) 和 [Rust canonicalize 文档](https://doc.rust-lang.org/std/fs/fn.canonicalize.html)。Windows 长路径回归仅完成交叉编译检查，未运行实机。

验证：先写递归/分页/空目录、失败与取消、非法名字/路径和冲突测试，再实现；界面测试覆盖文件夹选择、批次加入、取消后晚到消息、名称实际绘制左边缘。最后全量测试、双平台 clippy、Windows release、更新文档及 ZIP。
